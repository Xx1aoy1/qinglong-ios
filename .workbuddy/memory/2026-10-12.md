## 追加：依赖列表「缓冲半天」的根因与二次优化（同日晚）

用户二次反馈「还是有点卡卡的，打开依赖缓冲半天」。

### 根因（对照青龙后端源码 v2.22.0 / v2.23.0 核实）

`GET /api/dependencies`（`back/api/dependence.ts` → `DependenceService.dependencies()`）在面板侧有两处重开销：

### 重要发现：Git Data API 创建的提交对象「结尾不带换行」

- 真实 `git commit` 生成的 commit 对象，message 后带一个 `\n`；
- `POST /git/commits` 服务端生成的是「头 + 空行 + message」，**没有**尾换行（`POST /git/tags` 同理）。
- 所以「本地 git 提交」与「API 创建提交」即使内容等价，**SHA 永远不同**。旧提交 `962197ee` 必须**补**一个换行才吻合；重写后的 `f19f3e1e` 必须**不补**才吻合。
- 副作用：`GET /git/commits/{sha}` 返回的 `message` 会丢掉尾换行；拿它重建对象前必须**两种变体都试**，取 SHA 吻合的那个。

### 本地对齐「物化」法（已验证，可复用）

本沙箱 `github.com` 不可达、`git fetch` 不可用，故用物化法把远端对象搬回本地：

1. `GET /git/trees/{sha}`（**非递归**，字段是 `path` 而不是 `name`）拉全 109 个 tree + 134 个 blob；
2. blob 用 `git hash-object -t blob -w --stdin` 写入；tree 用 `git mktree` 写入（必须**子节点优先**、自底向上，否则 mktree 找不到子对象）；
3. commit / tag 用 `git hash-object -t commit|tag -w --stdin` 写入，尾部换行的两种变体逐一试；
4. `git update-ref refs/heads/main` + `refs/tags/*`，最后 `git reset` 刷新索引。

-> **本地 SHA 与远端逐字节一致**。该脚本（`ql_materialize.py` / `ql_write_commits.py`）是今后「API 推送后把本地拉回一致」的标准手段。
