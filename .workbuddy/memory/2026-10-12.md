- 可行方案：**用 GitHub Git Data API 建提交**（全走 api.github.com）

  （已验证均为 `720cd3c3e3060b897e4a22cc1028b1c834ea2236`）。
  在有正常网络的环境下需先 `git fetch origin && git reset --hard origin/main` 对齐，避免非快进冲突。

## 追加：修复「数据解析失败」——青龙 2.22+ 接口兼容（同日下午）

用户实机（面板 v2.22.0，master）反馈：概览报「数据解析失败，可能面板版本不兼容」，任务/变量列表刷不出来。

### 根因（对照 v2.22.0 / v2.23.0 后端源码逐接口核实）
1. **`/api/crons` 在 2.22+ 已分页化**：返回 `{ code:200, data:{ data: Crontab[], total } }`（`crontabs()` 签名即 `Promise<{data, total}>`），客户端按纯数组解码 → 必然 typeMismatch。**2.23.0 同样如此**（此前研读 develop 时误判为纯数组）。其余列表接口（envs/subscriptions/dependencies/apps）两个版本都仍是纯数组。
2. **`/api/user/login-log` 在 2.22+ 返回扁平 info 对象数组**（`result.map(x => x.info)`，即 `{timestamp,address,ip,platform,status}`，无 id/type 包裹），客户端按 `{id,type,info}` 解码 → 全部字段为 nil。
3. log 接口（`/:id/log`）两版本一致：`{code, data:content, logStatus, offset, nextOffset, total, truncated}` ✓

### 修复（3 文件）
- 新增 `CronListPage: Decodable`（singleValueContainer 先试 `[QLCron]`，失败再按 `{data,total}` 取），`CronService.list` 改用它
- `LoginLogItem` 自定义 `init(from:)` 兼容嵌套/扁平两种形态
- `APIError.decoding` 文案在正式版也携带字段路径（便于以后定位）

### 连带踩坑 ×2（CI 各失败一轮）
1. **`Vfjxct` 损坏这次是真的写进了文件**：QLUser.swift 4 处 `String.self` 被写成了 `Vfjxct.self`（此前判定纯为渲染假象，本次证实编辑写入层也可能损坏）。全工程字节扫描 + 批量替换修复。**教训：每次 Edit 后必须字节级复核关键文件。**
2. **CodingKeys 含与存储属性不匹配的 case 会阻断 Encodable 合成**：LoginLogItem 的 CodingKeys 加了 timestamp/address/ip/platform/status（只为解码用）→ `encode(to:)` 合成失败报 "does not conform to Encodable"。拆成 `CodingKeys(id/type/info)` + `FlatKeys(扁平字段, 仅解码)` 解决。

## 追加：列表页性能优化（同日晚）

用户反馈「打开任务/变量/依赖卡卡的」。

### 定位到的三个开销来源
1. **切 Tab 即重建 ViewModel 并重新请求**：TabView 切回列表就白屏 loading，感知为「卡」。
2. **派生数据在 `body` 里现算**：`filtered`/`labels`/各筛选 chip 计数是计算属性，一次渲染被读多次 → O(n log n) 重复几十遍；搜索每次击键全量重算。
3. **逐行 `WrapHStack`（FlowLayout）**：每行一次 `subview.sizeThatFits(.unspecified)` 测量；标签多的行在滚动时尤其明显。

### 改动（7 文件 + 1 新增）
- **新增 `QingLong/Core/App/ListCache.swift`**：进程内缓存（`NSLock`），存 crons/envs/subscriptions/dependences。`AppSession.switchTo/logout/forceLogout` 三处 `clear()`。
- **CronListView**：`crons/keyword/filter/selectedLabel` 加 `didSet` → 统一走 `recompute()` 一次算完 `filtered`/`labels`/`filterCounts`；`count(for:)`/`runningCount` 改读缓存；`init()` 命中 `ListCache`；搜索 180ms 防抖（`searchTask`）；`loadIfStale(maxAge: 20)`；`CronRow` 标签上限 2 个 + `+N`。
- **EnvListView**：派生值走 `refreshDerivedIfNeeded()`（以 `statusFilter|selectedLabel|keyword` 与 `envs` 做 memo key 比较，命中即复用）；`primeFromCache()` + `loadIfStale`。
- **DependenceListView**：同 CronListView 思路（`filtered`/`hasBusy` 缓存 + 防抖 + `loadIfStale`），保留原有轮询。
- **SubscriptionListView**：行内 `WrapHStack` → 单行 `HStack`，`tags`（`RowTag` 轻量载体）取前 3 个 + `+N`。
- 版本号 → 1.0.2。
