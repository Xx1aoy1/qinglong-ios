## 修复：编辑 config.sh 时删字符光标跳走

- 现象：配置文件编辑器（config.sh）里删掉一个字/一个字符，光标和视图位置就跳走，找不回原处。
- 根因：SwiftUI `TextEditor` 绑定的字符串每敲一键都变，父视图重算后 SwiftUI 会把整段文本重新写回底层
  `UITextView`，`selectedRange` / `contentOffset` 被一起重置；文本越长越明显。另有次要隐患：同一文件
  重复 `load()` 会把编辑框内容顶回服务器版本。
- 修复：
  - 新增 `QingLong/Design/CodeEditorView.swift`（`UIViewRepresentable` + `UITextView`）：
    只有 `view.text != text` 时才整体替换；用户输入触发的回写直接短路，光标完全不动；
    `markedTextRange != nil` 时跳过，避免打断中文输入法组词；顺手关掉自动更正/智能标点。
    文本内边距改用 `textContainerInset`，替换原来的 `.padding`。
  - `ConfigFilesView` / `ScriptEditorView` 两处编辑器改用该组件。
  - 两个 ViewModel 的 `load` 加 `loadedPath` / `loadedKey` 幂等保护 + `force` 参数。
  - 配置文件「重新读取」在有未保存修改时先弹确认。

  Release `QingLong-1.0.6.ipa` 2 829 407 B（arm64 thin、无签名、minOS 15.0、QLRepositoryURL 仅 GitHub），
  本地 `dist/QingLong-1.0.6.ipa` 已留存。

## 1.0.6 没修好 → 1.0.7 二次修复（真正的根因）

- 用户反馈：换成 `UIViewRepresentable` + `UITextView` 后，删一个字符照样跳走。
- **真正的根因**：`updateUIView` 里每次更新都无条件执行
  `view.textColor = …`、`view.isEditable = …`、`view.tintColor = …`。
  `UITextView` 这些 setter 会重建整段文本属性，**把 `selectedRange` 顶到末尾** ——
  每次按键 → 写 binding → SwiftUI 重算 → `updateUIView` → 光标被顶走。
  只包 UITextView 而不清理副作用，等于没修。
- 修法（两道保险）：
  1. `Coordinator` 缓存 `appliedScheme / appliedEditable / appliedFontSize / appliedInsets`，
     只有任一变化（深浅色切换、配置改动）时才 `applyAppearance`，并在改完把 `selectedRange` 放回去。
     纯输入路径一个 setter 都不碰。
  2. 编辑文本脱离 `@Published`：`private(set) var content` + `var textBinding: Binding<String>`，
     输入只更新 `isDirty`（仅 false↔true 翻转时通知）+ 220ms 防抖的 `charCount`。
     输入过程 SwiftUI 完全不重算，`updateUIView` 连调用都不会发生。
- `ConfigFilesView` / `ScriptEditorView` 的 `hasChanges` 在 View 层统一换成 `isDirty`，
  `content.count` 换成 `charCount`，`$viewModel.content` 换成 `viewModel.textBinding`。
- 发布：commit `782c2f9078`、tag `v1.0.7`（tag 对象 `5440c1b3`）、CI run 40075343351 success、
  Release `QingLong-1.0.7.ipa` 2 834 956 B，本地 `dist/QingLong-1.0.7.ipa`。
- 教训：改 UIKit 包装组件时，`updateUIView` 必须当作「纯 diff 函数」，任何赋值都要先比较；
  `textColor` / `font` / `textContainerInset` 这类属性 setter 都有重置光标的副作用。
